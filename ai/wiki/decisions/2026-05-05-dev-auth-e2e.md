# Tytuł
Dev auth jako jawny wybór użytkownika i scenariusz E2E.

## Podsumowanie (TLDR)
- Strona `/login/dev` nie może linkować bezpośrednio do OAuth2 callback `/login/oauth2/code/dev`.
- Wybór konta dev przechodzi przez `/login/dev/select`, który zapisuje profil dev w sesji Spring Security.
- Przy backendzie na `/hexabid` i SPA na `/` cookie sesji musi mieć `Path=/`, inaczej requesty SPA `/api/me` przez proxy kończą się 401.
- Playwright ma osobny smoke test `npm run e2e:auth`, który sprawdza account picker, wybór użytkownika i profil `/api/me`.

## Tagi
#auth #dev-auth #oauth2 #spring-security #e2e #playwright

## Treść
Problem: przycisk "Login as this user" prowadził do technicznego callbacku OAuth2. Callback wymaga poprawnego `code` i `state`, więc ręczne wejście po wyborze konta kończyło się `/login?error`.

Decyzja:
1. Strona `/login/dev` renderuje katalog użytkowników dev oraz bezpieczny redirect target.
2. Kliknięcie użytkownika prowadzi do `/login/dev/select?username=...`.
3. Endpoint `select` tworzy `OAuth2AuthenticatedUser`, zapisuje `SecurityContext` w sesji HTTP i przekierowuje do SPA.
4. Parametr `redirect` jest dopuszczony tylko dla ścieżek względnych albo lokalnego SPA `localhost:14200` / `127.0.0.1:14200`.
5. `server.servlet.session.cookie.path=/` pozwala przeglądarce wysłać `JSESSIONID` także dla `http://localhost:14200/api/...`, które Angular dev server proxy przekazuje do backendu.
6. Test E2E startuje z `/oauth2/authorization/dev` na SPA, wybiera użytkownika i sprawdza, że dashboard nie pokazuje już komunikatu o braku logowania.
