:toc: macro
:toclevels: 3
:sectnums:
:source-highlighter: coderay

toc::[]

== TLDR

Wprowadzenie modułu `hexabid-statements` opartego na **algorytmach grafowych** (DAG, sortowanie topologiczne, analiza osiągalności), modelującego oświadczenia kandydatów jako węzły w grafie zależności. Typ aukcji określa **szablon oświadczeń** — zbiór wymaganych oświadczeń z przypisanymi fazami zbierania. Odrzucenie dowolnego oświadczenia kaskadowo unieważnia wszystkie zależne i natychmiast powiadamia kandydata o wykluczeniu z podaniem konkretnej przyczyny.

== Kontekst

=== Problem

Obecny system nie posiada koncepcji **oświadczeń** (declarations/statements) składanych przez kandydatów do udziału w aukcji. Istnieje `DocumentType` z `DocumentStatus`, ale to system **dowodów dokumentowych**, nie oświadczeń. Brakuje:

1. **Typu aukcji** — `Auction` nie ma pola określającego mechanizm aukcyjny (angielska, holenderska, przetarg, itd.)
2. **Oświadczeń** — biznes wymaga od kandydatów oświadczeń (niekaralność, brak konfliktu interesów, sytuacja finansowa, itd.) przed dopuszczeniem do licytacji
3. **Zależności między oświadczeniami** — oświadczenie A może być warunkiem koniecznym oświadczenia B
4. **Faz zbierania** — oświadczenia zbierane są w krokach, a na końcu zapada decyzja o udziale
5. **Natychmiastowe powiadomienie o odrzuceniu** — jeśli oświadczenie zostanie odrzucone, kandydat natychmiast wie, że nie może wziąć udziału i dlaczego

=== Archetypy i inspiracje

| Archetyp / Wzorzec | Zastosowanie |
|---------------------|-------------|
| Algorytmy grafowe (DAG) | Graf zależności oświadczeń — cykliczny graf skierowany bez cykli |
| Sortowanie topologiczne | Określanie kolejności zbierania oświadczeń |
| Analiza osiągalności (reachability) | Kaskadowe odrzucenie: unieważnienie wszystkich oświadczeń osiągalnych z odrzuconego |
| Domknięcie przechodnie (transitive closure) | Szybkie określanie wpływu odrzucenia bez traversowania grafu |
| Archetyp Rules (M04) | Oświadczenie jako reguła z severity i fazą |
| Archetyp Pricing (M03) | Kompozyt oświadczeń analogiczny do CompositePriceComponent |

== Decyzja

=== Typy aukcji jako szablony oświadczeń

Zamiast prostego enuma `AuctionType`, typ aukcji jest **szablonem** określającym:

. Które oświadczenia są wymagane
. W jakiej fazie zbierania
. Z jaką wagą (BLOCKING / WARNING / INFORMATIVE)
. Czy aukcja ma fazy prekwalifikacji

[source,java]
----
sealed interface AuctionKind permits
    EnglishAscending,
    SealedBidTender,
    RestrictedTender,
    DutchDescending {

    String label();
    DeclarationTemplate declarationTemplate();
    boolean hasPrequalification();
}
----

==== Własności grafu

. **Jeden korzeń**: `LEGAL_CAPACITY` — jedyny węzeł bez krawędzi wchodzących (poza `DATA_PROCESSING_CONSENT` które jest opcjonalne w niektórych aukcjach)
. **Jeden liść-commitment**: `ACCEPTANCE_OF_TERMS` — węzeł bez krawędzi wychodzących, finałowa zgoda
. **Węzły bifurkacyjne** (stopień > 2): `LEGAL_CAPACITY`, `FINANCIAL_STANDING`, `TECHNICAL_COMPETENCE`
. **Węzły konwergencyjne** (stopień wejściowy > 1): `ANTI_CORRUPTION` (2 wejścia), `SUBCONTRACTOR_DISCLOSURE` (2 wejścia), `ACCEPTANCE_OF_TERMS` (2 wejścia), `FINANCIAL_STANDING` (2 wejścia)
. **Acykliczność**: Gwarantowana przez konstrukcję — oświadczenie z niższej fazy nie może zależeć od oświadczenia z wyższej fazy

=== Fazy zbierania oświadczeń

Oświadczenia zbierane są w **czterech fazach** odpowiadających rosnącemu poziomowi zaangażowania. Faza musi być zamknięta (wszystkie BLOCKING oświadczenia złożone) przed przejściem do następnej.

[cols="1,2,3,2"]
|===
| Faza | Nazwa | Cel | Oświadczenia

| 1 | TOŻSAMOŚĆ | Weryfikacja kim jest kandydat i czy może działać prawnie | `LEGAL_CAPACITY`, `IDENTITY_CONFIRMATION`, `DATA_PROCESSING_CONSENT`
| 2 | KWALIFIKACJA | Weryfikacja czy kandydat spełnia wymogi prawne | `NO_CRIMINAL_RECORD`, `NO_CONFLICT_OF_INTEREST`, `TAX_COMPLIANCE`, `SOCIAL_SECURITY_COMPLIANCE`

=== Kaskadowe odrzucenie (Cascade Rejection)

**Kluczowa własność systemu**: odrzucenie oświadczenia powoduje natychmiastowe unieważnienie wszystkich oświadczeń osiągalnych z niego w DAG (domknięcie przechodnie po krawędziach zależności).

==== Algorytm

[source,java]
----
Set<DeclarationType> computeCascadeRejection(DeclarationType rejected, DeclarationDAG dag) {
    // Domknięcie przechodnie: wszystkie węzły osiągalne z 'rejected'
    Set<DeclarationType> cascade = dag.reachableFrom(rejected);

    // Dla każdego osiągalnego: status → REJECTED_CASCADE
    // Powód: "Oświadczenie X zostało odrzucone, co unieważnia oświadczenie Y"
    return cascade;
}
----

==== Przykład kaskady

Kandydat oświadcza, że nie ma zaległości podatkowych (`TAX_COMPLIANCE` = SUBMITTED). System weryfikuje i **odrzuca** (bo zaświadczenie z US wykazało zaległość).

Kaskada:

....
TAX_COMPLIANCE [REJECTED]
    └──→ FINANCIAL_STANDING [REJECTED_CASCADE: "Zaległości podatkowe unieważniają oświadczenie o sytuacji finansowej"]
          ├──→ INSURANCE_COVERAGE [REJECTED_CASCADE: "Brak potwierdzenia sytuacji finansowej unieważnia ubezpieczenie"]
          └──→ WADIUM_COMMITMENT [REJECTED_CASCADE: "Brak potwierdzenia sytuacji finansowej unieważnia zobowiązanie wadium"]
                └──→ ACCEPTANCE_OF_TERMS [REJECTED_CASCADE: "Brak zobowiązania wadium uniemożliwia akceptację regulaminu"]
....

**Efekt**: kandydat natychmiast otrzymuje powiadomienie:

....

|===
| Warunek | Decyzja

| Wszystkie BLOCKING = SUBMITTED, żadne REJECTED | `PARTICIPATION_GRANTED`

==== DeclarationDAG — graf zależności

[source,java]
----
public final class DeclarationDAG {

    private final Set<DeclarationType> nodes;
    private final Set<DeclarationEdge> edges;
    private final Map<DeclarationType, Set<DeclarationType>> adjacency;
    private final ReachabilityIndex reachability;

    public Set<DeclarationType> reachableFrom(DeclarationType source) {
        return reachability.reachableFrom(source);
    }

    public Set<DeclarationType> prerequisitesOf(DeclarationType target) {
        return edges.stream()
            .filter(e -> e.to().equals(target))
            .map(DeclarationEdge::from)
            .collect(Collectors.toUnmodifiableSet());
    }

    public List<DeclarationType> topologicalOrder() {
        return TopologicalOrder.of(this);
    }

    public boolean hasCycles() {
        return TopologicalOrder.hasCycle(this);
    }

    public Set<DeclarationType> roots() {
        return nodes.stream()
            .filter(n -> prerequisitesOf(n).isEmpty())
            .collect(Collectors.toUnmodifiableSet());
    }

    public Set<DeclarationType> leaves() {
        return nodes.stream()
            .filter(n -> adjacency.getOrDefault(n, Set.of()).isEmpty())
            .collect(Collectors.toUnmodifiableSet());
    }
}

==== ReachabilityIndex — domknięcie przechodnie

Prekomputowane przy budowie DAG. Algorytm Warshalla-Floyda lub DFS per node.

[source,java]
----
public final class ReachabilityIndex {

    private final Map<DeclarationType, Set<DeclarationType>> reachable;

    public Set<DeclarationType> reachableFrom(DeclarationType source) {
        return reachable.getOrDefault(source, Set.of());
    }

    public boolean isReachable(DeclarationType from, DeclarationType to) {
        return reachable.getOrDefault(from, Set.of()).contains(to);
    }

    public static ReachabilityIndex compute(DeclarationDAG dag) {
        // Floyd-Warshall or iterative DFS
        Map<DeclarationType, Set<DeclarationType>> result = new HashMap<>();
        for (DeclarationType node : dag.nodes()) {
            result.put(node, computeReachable(node, dag));
        }
        return new ReachabilityIndex(result);
    }
}

==== CascadeRejectionEngine — silnik kaskady

[source,java]

public final class CascadeRejectionEngine {

    private final DeclarationDAG dag;

    public CascadeRejectionResult cascade(DeclarationType rejected, RejectionReason reason) {
        Set<DeclarationType> cascadeTargets = dag.reachableFrom(rejected);
        List<CascadeRejection> cascadedRejections = new ArrayList<>();

        for (DeclarationType target : cascadeTargets) {
            RejectionReason cascadeReason = RejectionReason.cascaded(
                sourceType = rejected,
                sourceReason = reason,
                targetType = target,
                dependencyDescription = dag.edgeBetween(rejected, target).reason()
            );
            cascadedRejections.add(new CascadeRejection(target, cascadeReason));
        }

        return new CascadeRejectionResult(rejected, reason, cascadedRejections);
    }
}

== Algorytmy grafowe — szczegóły

=== Sortowanie topologiczne

Określa kolejność zbierania oświadczeń wewnątrz fazy. Jeśli DAG jest:

....
LEGAL_CAPACITY → IDENTITY_CONFIRMATION → NO_CONFLICT_OF_INTEREST
....

To kolejność tożsamości: `[LEGAL_CAPACITY, IDENTITY_CONFIRMATION]`, a kwalifikacja: `[NO_CONFLICT_OF_INTEREST]`.

Algorytm: Kahn's algorithm (BFS-based) — deterministyczny porządek alfabetyczny przy remisach.

[source,java]
----
public final class TopologicalOrder {

    public static List<DeclarationType> of(DeclarationDAG dag) {
        Map<DeclarationType, Integer> inDegree = computeInDegree(dag);
        Queue<DeclarationType> queue = new PriorityQueue<>(Comparator.comparing(DeclarationType::name));

        dag.roots().forEach(queue::add);
        List<DeclarationType> result = new ArrayList<>();

        while (!queue.isEmpty()) {
            DeclarationType current = queue.poll();
            result.add(current);
            for (DeclarationType neighbor : dag.successorsOf(current)) {
                int newDegree = inDegree.merge(neighbor, -1, Integer::sum);
                if (newDegree == 0) queue.add(neighbor);
            }
        }

        if (result.size() != dag.nodes().size()) {
            throw new IllegalStateException("Declaration DAG contains a cycle");
        }

        return Collections.unmodifiableList(result);
    }
}
----

=== Analiza osiągalności (Reachability)

Prekomputowana przy budowie DAG. Dla każdego węzła przechowuje zbiór węzłów osiągalnych. Używana do:

1. **Kaskadowe odrzucenie** — `reachableFrom(rejected)` → zbiór do unieważnienia
2. **Wpływ zmiany** — gdy kandydat poprawia oświadczenie, które oświadczenia kaskadowe mogą zostać odblokowane
3. **Audyt** — „to oświadczenie wpływa na N innych oświadczeń"

=== Weryfikacja spójności DAG

Przy każdej modyfikacji szablonu (dodanie typu aukcji, zmiana zależności):

1. Sprawdzenie acykliczności (topological sort)
2. Sprawdzenie spójności faz (krawędź nie prowadzi z wyższej fazy do niższej)
3. Sprawdzenie korzeni (każdy spójny komponent ma przynajmniej jeden korzeń w Fazie 1)
4. Sprawdzenie liści (każdy spójny komponent ma przynajmniej jeden liść w Fazie 4)

== Konsekwencje

=== Plusy

* **Transparentność** — każdy kandydat wie dokładnie które oświadczenia są wymagane i w jakiej kolejności
* **Natychmiastowa informacja zwrotna** — odrzucenie powoduje kaskadę z precyzyjną przyczyną
* **Ekstensybilność** — nowy typ aukcji = nowy szablon; nowe oświadczenie = nowy węzeł w DAG
* **Audytowalność** — pełna historia oświadczeń z kaskadami, weryfikacjami i naprawami
* **Weryfikowalność** — graf DAG jest sprawdzany na acykliczność i spójność fazową przy każdej zmianie
* **Algorytmiczna poprawność** — sortowanie topologiczne gwarantuje poprawną kolejność; domknięcie przechodnie gwarantuje pełną kaskadę

=== Minusy

* **Złożoność** — 16 typów oświadczeń, DAG, kaskady, fazy — znacznie więcej niż obecny `DocumentType`
* **Migracja** — `Auction` potrzebuje `auctionKind`; istniejące aukcje muszą zostać przypisane do typu
* **Krzywa uczenia** — zespół musi zrozumieć DAG, sortowanie topologiczne, domknięcie przechodnie

=== Ryzyka

* **Nadmierne projektowanie** — nie każda aukcja potrzebuje 16 oświadczeń → *mitigacja*: szablony per `AuctionKind`; `DUTCH_DESCENDING` wymaga tylko 3
* **Cykliczne zależności** — błędna modyfikacja DAG może wprowadzić cykl → *mitigacja*: walidacja acykliczności przy budowie + ArchUnit test
* **Wydajność** — domknięcie przechodnie prekomputowane = O(N²) w pamięci → *mitigacja*: N=16 jest trywialne; nawet 1000 oświadczeń jest wykonalne
* **Spójność fazowa** — krawędź z niższej fazy do wyższej OK, odwrotnie nie → *mitigacja*: invariant w `DeclarationGraphFactory`
